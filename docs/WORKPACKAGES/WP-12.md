# WP-12: `console-picture-inbox`

Branch `feat/WP-12-console-picture-inbox`. Milestone N-M2. Owns the
manned picture layer, the coordination inbox, the audit view, the source
switches and the policy page in `web/`. Depends on WP-11 (the app),
WP-6 (feed stream), WP-10 (inbox stream). Consumer: the watch supervisor.

## Read first

1. `CLAUDE.md`, `docs/PLAN.md §6` (manned-traffic, coordination,
   sources, policy, audit operations), `§8`.
2. Spec `02 F4` (what a consumer must show: stale, unavailable, never an
   empty sky), `04 §2` (trust classes and `source_disabled`), `01 §4`
   N3 (acknowledgement), `05 §5` (console WS throttle, `dropped_frames`
   visible in the UI).
3. `uspace-ui` track symbology (trust class `surveillance`, age), the
   kit's bbox subscription hook.
4. LESSONS B-11, B-13 (holes are holes: a stale aircraft is drawn as
   stale at its last position with its age, never extrapolated), C-12,
   E-02; `scenarios.md` SC-08, SC-22.

## What to build

- Bump `@rootxkit/uspace-ui` to `≥ 0.3.0` (`MannedLayer`, `alerts`,
  M33) in a `build:` commit first.
- Manned picture layer on the restriction map: connects to
  `/v1/manned-traffic/stream` with the `uspace_session` cookie through
  the kit's `live` client and sends `console/subscribe/v1 {bbox,
  layers: ["manned", "all"]}` (M29);
  draws each aircraft with callsign, `icao24`, altitude (`alt_pressure_m`
  labelled as pressure altitude, `alt_wgs84_m` when present, never
  summed or converted in the browser), ground speed, track, age; states
  `live`, `stale (age)`, `source_disabled by <actor>`, `backlog`;
  relevant aircraft distinct from the rest; the `console/status/v1`
  frame (there is no `feed/status/v1`, M12) drives a status bar:
  `adapters[]`, `degraded[]`, `dropped_frames`, `cis_age_s`,
  `policy_version`, with the thresholds (`stale_after_s`,
  `live_max_age_s`) taken from that frame, never defaulted in the
  browser (INV-03). An empty stream shows `no aircraft reported;
  adapters: <states>` (SC-22).
- Coordination inbox: list by state with the escalated ones first and
  loudest; a notice shows its kind, sender, intents, authorisation
  numbers, volumes on the map, the restrictions it touches; acknowledge
  with a note; `intent_notice` and `ended` as informational; live via
  `/v1/coordination/stream`; a browser notification (opt-in) on
  escalation.
- Occurrence report form (`watch_supervisor`): the `occurrence/v1`
  fields, the 72 h deadline, delivery state; the reporter reference
  field marked as protected.
- Sources page (`admin`): switches by type and instance with reason;
  the API's `503` ("switch store unavailable, nothing changed") shown
  verbatim; current state with who and when (SC-08 steps 6–7 in the UI:
  a `viewer` sees no switch controls and the API's `403` is handled).
- Policy page (`admin`): the thresholds row with units, change with
  reason, history from audit.
- Audit view (`admin`): events by entity and time; export as JSON with
  the chain hashes.

## Tests

- Playwright against the mocked API and a mocked WS: an aircraft goes
  live → stale → `source_disabled` and the symbol and label change
  each time; the empty-stream text; an escalated notice appears first
  and the acknowledgement clears it; the `viewer` role sees no switch
  controls.
- Vitest: the frame reducer (ordering by `captured_at`, dropping older
  frames, ages) with its E-01 pairs; i18n key parity for the new pages.
