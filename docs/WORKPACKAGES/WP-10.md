# WP-10: `coordination-inbox`

Branch `feat/WP-10-coordination-inbox`. Milestone N-M2. Owns
`internal/coord`, `migrations/relational/0070–0079`
(`coordination_notices`, `occurrence_reports`), the coordination, inbox,
occurrence and `/v1/coordination/stream` handlers. Depends on WP-1,
WP-2, WP-3, WP-7 (USSP list for sender validation), WP-8 (occurrence
jobs ride the outbox). Consumer: the USSP (F13), the console (WP-12),
the authority (occurrences).

Safety note: Art. 13(2) obliges the ATS unit to acknowledge a
non-conformance alert. A notice that lands here and nobody sees is a
regulatory miss and, in controlled airspace, a safety one. The inbox
must make an unacknowledged notice loud within `notice_escalation_s`
and never lose one.

## What to build

- `POST /v1/coordination/annex-v` (scope `ansp.coordination`): the
  sender's `sub` must be on the CIS USSP list projection (`403` and an
  audit row otherwise; with no projection, accept and flag
  `sender_unverified: true`, counted, never refuse for lack of our own
  data); body bounded (1 MiB), validated field by field (`kind`,
  `intent_refs[]` UUIDs, `authorisation_numbers[]`, times, volumes
  through the `f3548` validators); stored in the same transaction as the
  `events` row and the `coord.v1.<kind>.<ack_id>` publish (B-05: `202`
  only after commit); the response `{ack_id, state: received,
  received_at}`. `msg_id` dedupe: a replay returns the same `ack_id` with
  `200`.
- At receipt: compute `restriction_ids[]` (active or planned
  restrictions whose geometry and window intersect the notice's volumes,
  via the envelope and PostGIS) so the console can show which
  restriction a notice touches.
- `GET /v1/coordination/notices/{ack_id}`: the sender (same `sub`) or a
  session reads `state`, `acknowledged_at`, `acknowledged_role` (never a
  name).
- Inbox: `GET /v1/coordination/inbox`, `POST
  /v1/coordination/inbox/{id}/acknowledge` (`watch_supervisor`, with an
  optional note; audited), `GET /v1/coordination/stream` (WS, session):
  new notices, acknowledgements, escalations.
- Escalation: a `nonconformance` or `contingent` notice not acknowledged
  within `notice_escalation_s` (60 s) gets `escalated_at` and an
  `escalation` frame on the stream every 30 s until acknowledged;
  counted `notices_escalated`; the console (WP-12) renders it as the
  loudest state. `intent_notice` and `ended` need no acknowledgement
  (recorded as `informational`).
- Restriction requests (F11) acceptance already lives in WP-5; this WP
  adds the console-side `POST /v1/restriction-requests` for a user and
  the stream events for new requests.
- Occurrences: `POST /v1/occurrences` (`watch_supervisor`): an
  `occurrence/v1` draft with the `04 §3.3` fields; `reporter.person_ref`
  encrypted at rest under `ANSP_SECRETS_KEY_FILE`, included in the body
  to the authority (which protects it under 376 Art. 16), never in any
  log, export or stream; `deadline_at = became_aware_at + 72 h` shown;
  an outbox job `occurrence` to the authority's `POST /v1/occurrences`
  (scope `occurrences.write`); delivery state on the report; a report
  undelivered 60 h after `became_aware_at` is an alarm.

## Tests

- Integration (NATS, PostgreSQL, a USSP stub as sender, an authority
  stub as receiver):
  - a valid notice → `202` with `ack_id`, a row, an event, a `coord.v1`
    message, `restriction_ids` filled when it intersects a fixture
    restriction (twin: empty when it does not); the stub reads the
    state `received`; a supervisor acknowledges → `acknowledged`, the
    stub reads it; the stream delivered both.
  - unknown sender `403` with the audit row; no projection → accepted
    with `sender_unverified` (E-02 for the degraded case, and the twin).
  - replayed `msg_id` → same `ack_id`, one row.
  - escalation at 60 s with a fake clock, repeated at 90 s, stopped by
    acknowledgement; `intent_notice` never escalates.
  - occurrence → authority stub receives it with the encrypted
    `person_ref` present and no name; delivery state `sent`; authority
    down → queued, alarm at 60 h (fake clock).
- E-10: 1 MiB + 1 body refused; 1 000 intent refs refused by bound.
- `FuzzAnnexVNotice`: never panics, never stores a refused body.
- A grep test: no log line, stream frame or export struct contains
  `person_ref` (reflection over the types that reach the stream).
